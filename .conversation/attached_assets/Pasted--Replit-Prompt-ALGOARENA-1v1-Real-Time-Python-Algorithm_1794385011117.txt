3. Core Features & Rules
A. Judge & Execution System (backend/judge.py)
Execution Timeout: 15s max per test case.

Test Case Separation:

Public Test Cases: 2–3 provided; run upon clicking "Run Code". Shows stdout, runtime, and simple pass/fail.

Hidden Test Cases: Minimum 10 hidden; run upon clicking "Submit Code".

Verdicts:

AC (Accepted): All test cases passed.

WA (Wrong Answer): Output mismatch.

TLE (Time Limit Exceeded): Exceeds per-problem time limit.

MLE (Memory Limit Exceeded): Exceeds memory limit.

RE (Runtime Error): Syntax or execution exception.

CE (Compile/Environment Error).

Note: Only AC deals damage and updates game points.

B. Point & Heart Mechanics
Difficulty Points:

BRONZE: 100 P

SILVER: 200 P

GOLD: 300 P

Hearts: Each player starts with 3 Hearts.

Damage: Successful AC reduces the opponent's heart count by 1 and plays a screen-shake/attack visual effect via WebSockets.

Win Condition: Opponent's hearts reach 0 OR higher health/points remaining when timer expires.

4. Real-Time WebSocket Communication Flow
Client connects to /ws/battle/{room_id}/{player_id}.

Real-time events synchronized:

PLAYER_JOIN: Both players ready.

CODE_SUBMITTED: Opponent submitted a solution.

ATTACK_EVENT: Opponent got AC, trigger damage animation & play sound/screen effect.

GAME_OVER: Displays summary modal with win/loss stats, total time, submission count, and points earned.
